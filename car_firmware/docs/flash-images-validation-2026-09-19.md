# 2026-09-19 首次烧录与参数保存实板验证

## 结论

双镜像构建和烧录流程已完成实板验证。空片、模拟其他固件残留时使用 factory，
可启动并继续保存参数；update 可逐字节保留原参数区。设备最终运行当前构建，
原始参数扇区已完整恢复，重心基准仍为用户此前保存的 **7.4°**。
使用方法见 [烧录说明](flash-images.md)。

## 环境与方法

- 芯片：STM32F411，设备 ID `0x10006431`，512 KiB Flash。
- ST-Link：V2J35M26；OpenOCD 0.12.0，使用 `STlink_hla.cfg`。
  探头持续报告低 Vref，但连接、擦写、校验、完整读回和复位均完成。
- 用户已断开电机线和舵机线。本次未接负载。
- 烧录前备份完整 524288 字节 Flash；SHA256：
  `4ff53a3d808bfb8c24b59514ee133805e100a64be8c28ddb462cad264934aa0d`。
- 烧录使用仓库生成的 `flash_factory` / `flash_update` CMake 目标。
  保存命令通过 SWD 注入现有 UART 接收队列，由真实命令任务执行；没有直接调用
  Flash 保存函数，也没有把测试参数作为运行时代码编入固件。
- 用 SWD 读取 Flash 后在主机比较整段数据，并用 Python `zlib.crc32` 独立校验记录。
  每次启动检查 `g_app_system_state=2`、硬件和任务失败位图均为 0、运动任务循环计数增长。

## 实板结果

| 场景 | 操作与结果 |
| --- | --- |
| 保留已有参数更新 | 烧录 update；整个 128 KiB 参数区与备份逐字节一致，复位恢复 7.4°；程序区读回与 BIN 一致 |
| 空芯片首次安装 | 擦除扇区 0–7，读回确认全部 512 KiB 为 `0xFF`；烧录 factory 后启动正常，参数区只有一条默认记录，其余字节全为 `0xFF` |
| 模拟其他固件残留 | 在程序尾部和参数扇区填入 `0xA5`，并在最后一个完整记录槽放入 CRC 有效、序号 999、重心基准 12.25° 的旧记录；factory 后整区只剩默认记录，加载 9.5° |
| factory 后保存 | 未调参的 save 不改变参数区；修改参数后 save 追加序号 2，CRC 与提交字正确；重复 save all 整区不变 |
| 已保存与未保存值 | 保存 10.75° 后，将 RAM 改为 6.25° 而不保存；复位恢复 10.75°，同时恢复手动 Kp 82、腿高 61.5 mm、横滚目标 -1.5°、电机死区 72 及其他已调 PID 值 |
| 再次保留参数更新 | 在上述调参状态烧录 update；整区逐字节不变，启动仍恢复已保存参数 |
| 空片直接烧 update | 全片擦空后烧 update；启动使用编译默认值，Flash 无有效参数记录；首次普通 save 写入有效默认记录，复位后正常加载 |
| 最终恢复 | 恢复原始参数区的全部字节和历史记录；重新复位检查，重心基准为 7.4°，程序区仍与当前构建一致 |

默认记录长度 84 字节、v3、序号 1、CRC `0x33738388`，重心基准 9.5°，
角度 Kp 基准 75.35，自动模式，腿高 44.5 mm，横滚目标 0，电机死区 0。
factory 烧录的整区读回证明末尾旧记录及未使用尾部字节均已擦除。
